# @service/product — RFC implementation

Новое приложение сервиса управления товарами. Предыдущая реализация сохранена
в `../_service` как reference и не является источником целевых бизнес-правил.

Источник принятых решений: workspace `agent/docs/rfc-product-constructor.md`.
Область реализации и проверки: `../../REWRITE-CONTRACT.md`.

- Следовать ООП и соглашениям NestJS старого сервиса: DTO-классы,
  `class-validator`/`class-transformer`, injectable services и регистрация через
  modules. Не заменять DTO ручными проверками типов и собственными парсерами.
- Транспортные DTO принадлежат `controller/dto`, один контракт на файл. Сервисы
  и репозитории не импортируют DTO; controller переводит их в команды приложения.
- Только каталог: примитивы, типы, товары, варианты, значения и связи изображений.
- Категории, склад, учет, цены, резервы и заказы принадлежат другим сервисам.
- Property, PropertyOption, Unit и Brand идентифицируются ручными кодами.
  ProductType, Product и Variant используют UUID; Image сохраняет UUID внешнего
  файла. Не добавлять Product/Variant дополнительный `code`.
- Unit хранит необязательное `description` в PostgreSQL `text`. При PATCH omission
  сохраняет описание, `null` или пустая строка очищает; изменение учитывает версию.
- Product/Variant никогда не удаляются: active/archived, редактирование архива
  разрешено; состояние родителя не переписывает личные состояния вариантов.
- Изображения товара связаны с Variant; Image — проекция файла, не байты/URL.
- Изображение бренда принадлежит бренду. При замене или очистке изображения
  новые связи, удаление старой проекции и событие `brand.images.removed`
  записываются одной транзакцией. Payload содержит `imageUuids`; File service
  удаляет старые объекты асинхронно. Сохранение того же UUID не вызывает удаления.
- Required/multiple задаются полем типа; Property определяет вид значения и единицу.
- Дробные характеристики Product/Variant хранятся в `numeric` без фиксированного
  масштаба. Миграция `UseVariableDecimalScale` приводит старые значения к краткой
  записи; общая PostgreSQL-функция `normalize_property_decimal` через триггеры обеих
  таблиц делает это для новых INSERT/UPDATE. В коде сервисов и клиентов нули не обрезаются.
  `valueDecimal` остаётся строкой; прежние границы числа сохраняются CHECK-ограничением.
- При удалении поля типа назначения и значения удаляются каскадно.
- Product создается для одного неизменяемого ProductType; смена typeUuid при PATCH не поддерживается.
- Product разрешено создавать без вариантов. Каждый Variant добавляется отдельным процессом; прежнее атомарное создание с variants сохраняет совместимость. PATCH явный, omission не archive.
- Полные снимки Product читаются через ProductSnapshotService с relationLoadStrategy query. Не добавлять nested SQL order: он возвращает перемножающие JOIN. Сортировка загруженных коллекций сохраняет прежний контракт.
- Variant mutations сохраняют полный Product в ответе и product.updated schemaVersion=3; узкие getAll/getByUuid вариантов не заменяют интеграционный снимок.
- Команды проверяют актуальность сущности и структуры типа; Variant mutations
  не должны обходить проверку версии товарного агрегата.
- `synchronize: false`; изменения схемы только явными миграциями. Старую БД
  и очереди нового несовместимого контракта нельзя переключать неявно.
- Опции принадлежат Property типа OPTIONS. Не добавлять отдельный справочник
  списков и не вводить удаление используемой опции без нового решения RFC.
- Общая outbox-инфраструктура принадлежит `../library/sellgar.outbox.library`;
  расширение ее контракта требует согласованной области задачи.
- Входящие интеграционные события проходят через `InboxModule`; запись inbox и
  изменение локальной проекции выполняются одной транзакцией. Исходящие события
  агрегата записываются через `ProductOutboxModule` в его доменной транзакции.
- Проверять реальные бизнес-правила, транзакции, FK и негативные сценарии;
  успешная сборка сама по себе не подтверждает поведение БД.

## Поиск товаров

- `getAll.term` использует PostgreSQL FTS, один `product.search_vector` и один
  GIN-индекс `product_search_vector_idx`. Вектор не входит в публичную Entity.
- Документ содержит только название товара (вес A), название бренда и названия
  активных вариантов (вес B). Описания, свойства, коды/UUID, изображения и данные
  Store не индексируются этим поиском.
- `product_search_query` сочетает поиск по началу слова (`simple`) и русские
  словоформы (`russian`); несколько слов соединяются через AND. SQL получает term
  параметром. Выдача сортируется по релевантности, затем UUID для стабильной пагинации.
- Миграция поддерживает вектор триггерами на product.name/brand_code,
  variant.name/status/product_uuid и brand.name. Изменения описаний и свойств
  вектор не пересчитывают. Версии агрегатов, timestamps и outbox этим не меняются.
- Проверка на реальном PostgreSQL запускается из `service`:
  `PRODUCT_SEARCH_DATABASE_TESTS=1 node --env-file=.env ../node_modules/jest/bin/jest.js product-fulltext.integration.spec.ts --runInBand`.
  Тест создает отдельную схему в транзакции и откатывает ее вместе с данными.
  Обычный unit-run этот тест пропускает, не подключаясь к БД.

Проверки из `code/`: `yarn build:product_srv`.
Из `code/service`: `yarn test --runInBand`.

Внутренний `GET /health` на `PORT` (default 8080) отражает PostgreSQL и оба
RMQ consumer. Доменные команды и event-контракты при деплое не изменяются.

## Выборка характеристик для витрины

- `catalog.v2.product.getByUuid` принимает необязательный boolean `withEmptyProperties`.
  По умолчанию `true`: полный набор полей шаблона для админки.
- При `false` repository выбирает назначения, для которых существуют строки значений
  (`EXISTS`), отдельно для товара и каждого варианта. Ноль и false являются значениями.
  Определения полей и options загружаются через назначения, пустые поля шаблона не читаются.
- Это read-only режим: шаблон, admin variant reads, mutations и полные outbox-снимки
  не меняются. Никакой фильтрации свойств в Client gateway и frontend.
- PostgreSQL-проверка: `PRODUCT_SNAPSHOT_DATABASE_TESTS=1 yarn test --runInBand product-snapshot.integration.spec.ts`.
